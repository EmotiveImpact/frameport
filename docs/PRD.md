# Product definition

**Working name:** Frameport. **Owner workspace:** Emotive Impact. **Current release:** 0.1.0 developer build.

## User outcome

An authorised designer/developer enters a published website address and receives independently editable React/TypeScript or HTML/CSS, accompanied by understandable evidence of what survived conversion and what needs review. The product should let someone continue building, not merely display a screenshot or repeatedly send them back to Framer.

## Current user journey

Open the local studio, confirm permission, choose page coverage and submit. Watch actual worker stages. Inspect captured pages at desktop/tablet/mobile widths, compare source/export/difference images, browse generated files, edit content fields, regenerate exports and review updated evidence. Download React or HTML archives with their reports and asset provenance. Cancel or retry failed work. Optionally attach a bounded project/CMS manifest.

## Release acceptance

A supported original fixture must generate two editable formats without source JavaScript or an HTML-string React wrapper. Text edits must alter both outputs, remain escaped, invalidate old revision evidence and produce a new archive. Visual evidence must use real full-height image dimensions and disclose its scope. Failure must be visible and must not serve an apparently successful old ZIP. API and network policies require regression tests. Every unverified external integration must be named rather than marketed as complete.

## Non-goals of 0.1

Universal fidelity; recovery of original Framer abstractions; backend/account/payment migration; automatic complex animation or WebGL reconstruction; an AI repair loop; a published marketplace plugin; multi-tenant hosted operations; or an unqualified 100% guarantee. The connected manifest currently adds reference metadata, not a complete canvas compiler.

## Measures for the next gates

Track capture completion by authorised fixture class, separately measured HTML and React visual results, explicit interaction checks, independence from declared runtime services, editability checks, actionable warning counts, conversion time/resource costs and regression failures. Do not collapse these into a single misleading fidelity score.
